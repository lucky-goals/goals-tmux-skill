# v0.3.0

Expanded workflow setup with batch model selection and safe partial updates to
existing generated YAML preferences.

## Changes

- Show one complete, globally numbered model table across selected CLIs and
  accept multiple model/effort combinations in one input line. Preserve input
  order, exact model IDs, and ordered scenario fallbacks.
- Add `setup-workflow.sh --edit [PATH]` to add profiles or edit selected
  scenario routing without regenerating unrelated preferences. Preview the
  diff, confirm once, and save with an exact-byte backup; no-op, cancellation,
  unsupported YAML, and stale-target detection avoid unintended writes.
- Allow ordered fallbacks for Review as well as other scenarios. Review still
  defaults to no fallback unless explicitly configured.
- Document catalog provenance, partial editing, fallback selection, and limits
  in the setup guide and localized READMEs.

## Validation

- 42 focused tests passed across model setup, edit mode, and the bounded workflow
  parser/editor. No full test suite was run.
- Packaged shell-flow checks covered batch model selection, adding a profile,
  editing only Review, scenario-only editing without installed CLIs, ordered
  Review fallbacks, exact backups, and preservation of unrelated configuration.
- No Python process used reload mode.

## Limits

- Edit mode supports the restricted YAML format emitted by this wizard, not
  arbitrary hand-written YAML.
- Workflow preferences remain authoring data. The runtime does not automatically
  load these YAML files or enforce their routing, permissions, or concurrency.
- Model discovery and CLI-reported effort values do not establish account
  entitlement or successful model execution.
