# v0.4.1

Setup wizard asks `permission_mode` per scenario instead of per CLI.

## Changes

- **Creation flow**:
  - Removed the per-CLI permission preference prompt that followed the global model/effort batch. `configure_pool()` now only adds target strings to the working pool and records unverified model/effort fields.
  - For each scenario given a primary target, the wizard asks one scenario-level `permission_mode` question after the primary and ordered fallbacks are chosen. It applies to the primary and every fallback. `1`/`d`/`default` (the default) or `2`/`b`/`bypass`; `q` cancels the wizard. Choosing bypass still shows the existing warning that YAML cannot authorize the current task.
  - A skipped scenario gets `target: null`, `fallbacks: []`, `allow_fallback: false`, `permission_mode: "default"` and no permission prompt.
- **Edit flow**:
  - Adding targets to the working pool no longer asks a permission question.
  - Editing a scenario asks the scenario-level `permission_mode` after target and fallback selection: `1` default, `2` bypass, blank keeps the current value, `q` cancels. Clearing the primary (`0`) sets `default` without asking.
  - The working pool is still seeded from existing targets and fallbacks, but per-target permissions are no longer derived from it.
- **Removed**: `SetupWizard._select_permission_mode()`, the `target_permissions` attribute, the mixed-permission resolver `_resolve_scenario_permission()`, and the `(permission_mode=bypass)` suffix in target listings. Added `_ask_scenario_permission()`.
- Diff preview, backup, stale-target detection, no-op save and destination behavior are unchanged.
- **Docs and version**: updated `references/workflow-setup.md` and the four README variants to describe the per-scenario prompt; bumped version to `0.4.1` in `runtime/pyproject.toml`, `runtime/goals_tmux/__init__.py` and `SKILL.md`.

## Validation

- `python3 -m unittest tests.test_setup_wizard tests.test_setup_wizard_edit tests.test_workflow_edit -v`: 59 tests passed (32 in `tests/test_setup_wizard.py`, 15 in `tests/test_setup_wizard_edit.py`, 12 in `tests/test_workflow_edit.py`).
  - New/updated coverage: no permission prompt after model selection; exactly one permission prompt per configured scenario, shown only after target/fallback answers; skipped scenarios get `default` without prompting; alias, reprompt and `q` handling; edit blank keeps current (including `bypass`), `2` sets bypass, `1` sets default, clearing primary forces default without prompting, `q` at the permission prompt cancels without writing.
- The full test suite was not run. No Python process used reload mode.

## Limits

- Existing generated files are unchanged until a scenario is edited; the YAML schema is unchanged (still `schema_version: 2`).
- Workflow preferences remain authoring data; the runner does not yet automatically load or enforce workflow YAML, and `bypass` never grants current-task authorization.
