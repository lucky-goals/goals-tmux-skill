# v0.2.6

Kiro CLI support, visible-window checks before task input, and an interactive
YAML configuration generator.

## Changes

- Add the `kiro` / `kiro-cli` adapter for launch and exact-ID resume arguments.
  Recovery checks bind evidence to the original pane/process, working directory,
  conversation metadata and task dispatch marker. Custom Kiro resume arguments
  preserve supported executable/model/effort options.
- Require fresh visible iTerm GUI evidence and a separate pane capture before
  dispatch, submission or raw task input when TUI is enabled. Creation validates
  a CLI metadata object and complete argv. Missing proof receives at most one
  remediation retry, then returns `TUI_REQUIRED` with reconciliation information
  instead of silently dispatching without a window.
- Add `scripts/setup-workflow.sh`, a Python-standard-library interactive wizard.
  It discovers installed CLIs, queries supported model catalogs, supports ten
  scenarios including HTML UI prototypes, UI implementation and UI automation,
  and offers exact model/effort selection, profile reuse, ordered fallbacks and
  per-CLI concurrency preferences. It previews YAML and saves to user or project
  scope only after confirmation; overwrites preserve a backup.
- Add bounded catalog discovery for Cursor, Codex, Antigravity and Kiro. Codex
  uses a read-only app-server handshake and `model/list`, with owned-process
  cleanup and no thread or model turn. Unknown/manual capabilities are clearly
  distinguished from discovered catalog entries.
- Document layered workflow configuration, all example fields/enums, and
  task-specific authorization. Require the host to disclose the YAML sources
  and effective profile before each project skill invocation. Update all four
  README languages and ship the wizard guide in the installation package.

## Validation

Focused adapter, TUI visibility/gate, recovery, viewer/configuration, wizard,
discovery and packaging checks passed during implementation. No full test suite
was run, and no Python process used reload mode.

- Real iTerm verification: visible input succeeded, minimized-window dispatch
  and input were blocked without new dispatch records, and restored-window
  input succeeded. Test resources were cleaned up.
- Kiro 3.1.0: visible launch, idle prompt, `/session-id` and normal `/quit` passed
  without a model request.
- Wizard: 11 focused tests; discovery: 14 focused tests; packaging: 2 tests.
  Temporary-directory end-to-end checks covered project/user saving, profile
  reuse, cancellation, exact overwrite backups and packaged standalone use.
- Local catalog discovery returned 270 Cursor, 8 Codex, 13 Antigravity and
  22 Kiro IDs. These are observations from the test environment, not fixed lists
  or guarantees for another account/version.

## Limits

- **Workflow YAML generation is implemented; automatic YAML loading, routing,
  authorization enforcement and per-CLI concurrency enforcement are not.** The
  generated preferences do not grant permissions or activate a workflow.
- The tested visible-proof path is ordinary iTerm2/tmux. Native `-CC` gateway
  presence, Terminal.app or manual attachment do not establish the required
  mapped GUI proof and will block the required visible workflow. Explicitly
  authorized headless execution remains separate.
- Kiro's tested V3 process exposed no process-bound transcript, so recovery
  correctly remained `unknown`. A complete model/context restore roundtrip was
  not verified. Older Kiro versions may differ in exact-ID resume support.
- Claude model discovery remains manual in this wizard. Catalog entries and
  CLI-level effort examples do not establish account entitlement, quota, or
  successful execution; unsupported selections must be checked before launch.
