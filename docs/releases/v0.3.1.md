# v0.3.1

Enhanced setup wizard destination selection with host-layer configuration and
safer path guidance.

## Changes

- Add host destination layer (`$XDG_CONFIG_HOME/goals-tmux-skill/hosts/<host-name>.yaml`,
  default host name `trae-cn`) alongside existing user and project destination options.
- Display layer precedence guidance (`user < host < project`) and fully resolved
  absolute paths for user, project, and host destinations in the setup wizard menu.
- Validate host names against `^[A-Za-z0-9][A-Za-z0-9._-]*$` (max 64 characters;
  reject empty names, path separators, `..`, and leading dots) with re-prompting
  on invalid input.
- Detect skill installation directories (directories containing regular files
  `SKILL.md` and `scripts/tmuxctl`, or named `goals-tmux-skill`) and require
  an explicit confirmation (default `n`) before saving project configuration
  there. Declining loops back to the destination menu without writing.
- Reuse existing atomic saving, preview, overwrite confirmation, and exact-byte
  backup logic for host configuration files.
- Document host destination layer, skill installation warning, custom-path editing
  for host files, and updated destination choices in documentation and localized READMEs.

## Validation

- 29 focused tests in `tests/test_setup_wizard.py` passed, covering:
  - Host destination with default name `trae-cn` and custom names, with XDG set and with `~/.config` fallback
  - Invalid host names rejected and no file written
  - Option 3 and aliases (`3`, `h`, `host`, `3/host`) selecting host path
  - Skill-installation-directory warning requiring explicit confirmation; declining loops back, accepting selects project path
  - Default selection remains option 2 (project)
  - End-to-end host destination file creation, mode 0600, parent directory creation, and exact-byte backup on overwrite
- 18 focused tests in `tests/test_setup_wizard_edit.py` and `tests/test_workflow_edit.py` passed without regressions.
- No full test suite was run. No Python process used reload mode.

## Limits

- Workflow preferences remain authoring data. The runtime does not automatically
  load or enforce workflow YAML.
- Host configuration files can be edited via `--edit` using the custom path option
  or by providing the path directly on the command line.
