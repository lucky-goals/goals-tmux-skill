# v0.4.0

Inline scenario targets in workflow schema version 2, replacing named profiles and CLI defaults.

## Changes

- **Breaking schema version bump to 2**:
  - Removed top-level `profiles` and `cli_defaults` entirely from the workflow template and emitted YAML.
  - Replaced named profile references in scenarios with inline target strings (`cli/model` or `cli/model/effort`).
  - Scenarios emit fields strictly in order: `label`, `permission_mode`, `target`, `fallbacks`, `allow_fallback`.
  - Unconfigured scenarios emit `target: null`, `fallbacks: []`, `allow_fallback: false`, `permission_mode: "default"`.
  - Target grammar: 2 or 3 non-empty non-whitespace segments separated by `/`. Two segments omit independent effort; three segments supply explicit effort. Rejects 1 segment, >3 segments, empty/whitespace segments.
  - Fallback constraints: ordered, no duplicates, primary target cannot appear in fallbacks, `allow_fallback` must equal `bool(fallbacks)`. Null target requires empty fallbacks and `allow_fallback: false`.
- **Parser and Editor updates**:
  - `workflow_edit.py` enforces integer `schema_version: 2`. Explicitly rejects `schema_version: 1` and any legacy `profiles`/`cli_defaults` with an error directing users to regenerate via `scripts/setup-workflow.sh`.
  - `patch_generated_yaml` reworked to accept scenario updates only (`target`, `fallbacks`, `allow_fallback`, `permission_mode`) and replace scenario source spans; removed profile-addition and unverified-profile parameters/logic while preserving comments, trivia, and exact-byte backup/diff behavior.
- **Setup Wizard updates**:
  - Creation flow: CLI scan, global model catalog table, cross-CLI batch input, and per-CLI permission preference maintained; named profile generation removed. Working pool stores transient target strings.
  - Mixed-permission scenario handling: when targets selected for a scenario have mixed permission modes, the wizard prompts for a scenario-level permission mode (default: primary target's mode), applying uniformly to target and all fallbacks.
  - Edit flow: seeds working pool from existing scenario targets and fallbacks (deduped, order preserved); allows adding targets (scan or manual) to pool and modifying scenario routes. Targets in pool that are not assigned to any scenario are transient and never persisted.
  - Unverified comments reference scenario targets and fallbacks rather than profiles.
  - Bypass comments summarize scenarios with `permission_mode: bypass`.
- **Documentation and Version**:
  - Bumped version to `0.4.0` across `pyproject.toml`, `goals_tmux/__init__.py`, and `SKILL.md`.
  - Updated `references/workflow-setup.md`, `docs/proposals/workflow-config.md`, `docs/proposals/workflow.example.yaml`, `docs/proposals/workflow.task.example.yaml`, and `docs/proposals/workflow-fields.zh-CN.md` for schema 2 inline targets, removing profile terminology.

  - 30 tests in `tests/test_setup_wizard.py`
  - 13 tests in `tests/test_setup_wizard_edit.py`
  - 12 tests in `tests/test_workflow_edit.py`

## Limits

- Breaking change: `schema_version: 1` workflows cannot be edited or parsed; users must regenerate with `scripts/setup-workflow.sh`.
- Workflow preferences remain authoring data; the runner does not yet automatically load or enforce workflow YAML.
